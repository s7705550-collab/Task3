Algorithmic Architecture: Why Vertical-Bitset Eclat + Ascending Support Ordering Works

Designed specifically for 2,000 items, 500,000 transactions, and deep planted bundles up to k = 10

Stage 1

CSR Token Flattening & `bincount`

Flattens all transactions into contiguous `int32` arrays and counts all 2,000 item frequencies in a single $O(N \cdot \bar{L})$ pass via `np.bincount`, immediately pruning ~80% of infrequent items ($2,000 \rightarrow 389$).

Stage 2

64-Bit Vertical Bitsets (`uint64`)

Packs each frequent item's transaction ID list into $\lceil N / 64 \rceil$ 64-bit words ($7,813$ words = $62.5\text{ KB}$ per item at $N=500\text{k}$). All 389 bitsets occupy only $24.3\text{ MB}$ in L3 cache.

Stage 3

Ascending-Frequency Eclat DFS

Sorts frequent 1-itemsets by ascending count before depth-first equivalence class intersection (`b & bj` + hardware `np.bitwise_count`). Sparser prefixes prune child branches immediately.

Stage 4

Downward-Closed Rule Generation

For each frequent itemset $X$ ($|X| \ge 2$), all proper subsets $A \subset X$ are already cached in `freq` in $O(1)$ lookup. Emits $A \Rightarrow X \setminus A$ whenever $\text{count}(X)/\text{count}(A) \ge 0.6$.
